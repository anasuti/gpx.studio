# AGENTS.md

## Layout

- `gpx-rs/`: pure Rust GPX engine. `core` (GPX data, algorithms, statistics), `engine` (stateful edits, commands, undo), `storage` (persistence), and `api` (DTOs + functions shared by both frontends).
- `wasm/`: `wasm-bindgen` bindings over `gpx_engine::api`, plus browser IndexedDB persistence. Output goes to `wasm/pkg` as the `gpx-wasm` npm package.
- `tauri/`: desktop shell. Runs the engine natively; its UI is the built `website`.
- `website/`: SvelteKit UI for both browser and desktop. `src/lib/engine/engine.ts` is the facade the rest of the UI must use; `src/lib/engine/backend/` selects WASM or Tauri.

## Build order (non-obvious)

The website depends on `gpx-wasm` via `file:../wasm/pkg`, so build the WASM package before installing, type-checking, testing, or building the website:

```bash
cd wasm && wasm-pack build --target bundler && cd ..
npm install --prefix website
```

Create `website/.env` with `PUBLIC_MAPTILER_KEY=...` (see `website/.env.example`, it is gitignored); without it the map layers fail. Website tests stub this variable.

Desktop: install the Tauri 2 CLI (`cargo install tauri-cli --version "^2"`), then `cd tauri && cargo tauri dev`. It starts the website dev server itself on port `4283`. Even though the desktop app uses the native engine, the website install still needs `wasm/pkg` present.

## Commands

- Engine tests: `cargo test` from the repo root. The workspace `default-members` is only `gpx-rs`, so this does not test the other crates.
- One Rust test: `cargo test -p gpx-engine <filter>`.
- WASM binding tests: `cd wasm && wasm-pack test --node`.
- Website tests: `npm test --prefix website` (requires the WASM build; the `pretest` hook runs `svelte-kit sync`).
- One website test file, from `website/` (run `npm run pretest --prefix website` first on a fresh checkout so `$lib` aliases exist):
  `node --import tsx --import ./src/test/register.mjs --experimental-wasm-modules --disable-warning=ExperimentalWarning --test src/lib/utils.test.ts`
- Website type-check: `npm run check --prefix website`.
- Lint / format: `npm run lint --prefix website` and `npm run format --prefix website` (Prettier config is the root `.prettierrc`; 4 spaces, single quotes, 100 columns).
- Desktop tests: `cargo test -p gpx-studio-desktop`. They are integration tests in `tauri/tests/app`; the crate sets `test = false` because Windows only gets the required manifest for test binaries.

## Engine API changes

A user-visible engine call crosses several layers. Update all of them together:

1. `gpx-rs/src/api/{commands,queries}.rs` (+ DTOs in `dto.rs`)
2. `wasm/src/{command,queries}/*.rs`, `wasm/src/selection.rs`, and hand-written TS types in `wasm/src/ts.rs`
3. `tauri/src/commands/*.rs` and registration in `tauri/src/lib.rs` (`generate_handler!`)
4. `website/src/lib/engine/backend/types.ts` plus both `wasm.ts` and `tauri.ts`
5. `website/src/lib/engine/engine.ts` facade (do not call a backend directly from components)

Cross-boundary conventions: ids go to WASM as one flat `Uint8Array` of 16-byte UUIDs, coordinates as `Float64Array`/`&[f64]`, file bytes as `Uint8Array`; avoid per-point calls. Mutations return an `Outcome` listing what changed; the facade serializes calls and re-reads only the affected files/order/selection. `revision` arguments are stale-UI guards, not identifiers.

## Generated and externally managed files

- `website/src/locales/*.json` and non-English `website/src/lib/docs/<lang>/**/*.mdx` come from Crowdin. English (`locales/en.json`, `docs/en`) is the source. Do not hand-edit translations.
- `website/src/lib/i18n/languages.ts` is the enabled-language list; locale files exist for more languages than are enabled. Tests check that every `i18n._('key')` exists in English and that enabled locales have no unknown keys.
- Help guides are ordered in `website/src/lib/components/docs/guides.ts` and prerendered for every enabled language, so a new guide needs the matching MDX in each enabled language or the build fails.
- `wasm/pkg/`, `website/build/`, `website/.svelte-kit/`, `target/`, and `website/static/*.webmanifest` (except `en.manifest.webmanifest`) are generated/ignored.
- `website/src/lib/data/example/example-data.ts` is generated by `npm run generate:example` after engine changes; it needs the WASM build.
- `website/src/lib/components/ui/` holds vendored shadcn-svelte components and is excluded from Prettier.

## Testing quirks

- Website tests run in Node, not a browser: SvelteKit virtual modules are stubbed in `website/src/test/hooks.mjs` and Svelte runes in `website/src/test/register.mjs`. Tests may import via `$lib`; CSS and `?url` imports are stubbed.
